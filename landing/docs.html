Architecture & Specification

Rekha Control Plane Architecture

Rekha (named after the engineering concept of a definitive boundary) is an open-source, air-gapped System-1 control plane for Retrieval-Augmented Generation (RAG). It provides a deterministic, sub-35ms inbound-to-outbound security and context envelope around your existing vector database and LLM.

The System-1 vs. System-2 Mental Model
Flawed Pattern: LLM-as-a-Judge (System-2)

Calling GPT-4o or Claude to check query safety or verify answers adds 1,500ms – 3,000ms of latency and costs $0.01 per query. Generative judges are susceptible to prompt injection bypasses.

Rekha Pattern: Non-Autoregressive Gate (System-1)

Evaluates query classification, intent caching, micro-chunk context pruning, and entity anchors in a single forward encoder pass in sub-35ms. Completely deterministic, air-gapped, zero external network calls.

// Global Request Flow Diagram
User Query ──► [ REKHA GATEWAY: INBOUND BOUNDARY ]
                 ├── Layer 1: Inbound Guard Gate   (Jailbreak & PII Filter: ~37ms)
                 ├── Layer 2: Smriti Intent Gate   (Zero-Cost Canonical Cache: <5ms)
                 └── Layer 3: Disha Query Router   (Bypass / SQL Tool / Vector: ~38ms)
                                     │
                                     ▼
               [ RETRIEVAL: CONTEXT PRUNING ]
                 └── Layer 4: Samkshep Slicer      (Syntax-Safe Pruning -54%: ~69ms)
                                     │
                                     ▼
               [ EXISTING PIPELINE ] ──► Vector DB ──► Model (GPT-4o, Claude)
                                     │
                                     ▼
               [ REKHA GATEWAY: OUTBOUND BOUNDARY ]
                 └── Layer 5: Satya Praman Gate    (Entity Anchor Audit: ~72ms)
                                     │
                                     ▼
                               Stream to User
Setup

Installation & Offline Weights

Rekha is distributed via PyPI. It has zero required cloud dependencies and runs entirely on your local CPU or GPU.

Terminal
$ pip install minelabs-rekha

Hardware Requirements:

  • Local CPU: Minimal footprint. Executes under ~35ms on standard modern 4-core cloud vCPUs (c6i, t4g, n2-standard).
  • GPU Acceleration (Optional): If PyTorch detects CUDA or Apple Silicon MPS, forward passes drop to sub-12ms.
  • Zero External Network Calls: At no point during inference does Rekha query OpenAI, HuggingFace Hub, or external telemetry servers.
Developer Ergonomics

60-Second Quickstart

Adding Rekha does not require restructuring your database, re-embedding vectors, or changing system prompts. Wrap your existing RAG execution function with the @gateway.protect decorator.

main_pipeline.py 
import openai
from rekha import RekhaGateway

# 1. Initialize the Gateway (loads local weights once)
gateway = RekhaGateway(
    target_context_reduction=0.50,  # Prune 50% of context noise
    negative_constraints=[
        "Do not disclose internal employee compensation.",
        "Do not cite discounts higher than 15%."
    ]
)

# 2. Decorate your existing RAG query function
@gateway.protect
def query_support_rag(query: str):
    # Fetch documents from your existing Pinecone/Chroma/Weaviate cluster
    docs = vector_store.search(query, top_k=5)
    raw_context = "\n\n".join([d.text for d in docs])

    # Synthesize answer using your model
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": f"Answer strictly using:\n{raw_context}"},
            {"role": "user", "content": query}
        ]
    )
    answer = response.choices[0].message.content
    return answer, raw_context

# 3. Call your function as usual
result = query_support_rag("What are our SLA response times for Tier-1 outages?")

print("Final Output:", result.final_output)
print("Execution Source:", result.source)          # "CACHE", "RAG_VERIFIED", or "BLOCKED_GUARD"
print("Control Overhead:", result.total_overhead_latency_ms, "ms")
Systems Engineering

The Latency Paradox Explained

Engineers often ask: "How can adding a 5-layer control plane make our RAG pipeline 600ms faster?" The math is rooted in transformer attention complexity.

Large Language Models incur a linear prefill penalty of approximately 0.45 ms per prompt token before emitting the first generated token (TTFT).
Traditional RAG (4,000 Tokens)
~1,800 ms TTFT

Full 4,000 retrieved tokens sent to the LLM. 50%+ of tokens are filler sentences, boilerplates, and navigational headers.

With Rekha Samkshep Slicing (1,832 Tokens)
~1,004 ms TTFT

+180ms control plane overhead - 976ms saved in LLM prefill time = Net ~796ms faster time to first token.

Integrate Rekha directly with LangChain chains or LangGraph state machine runnables.

langchain_rekha_adapter.py 
from langchain_core.runnables import RunnableLambda
from langchain_community.vectorstores import Chroma
from langchain_openai import ChatOpenAI
from rekha import RekhaGateway

gateway = RekhaGateway(target_context_reduction=0.55)
llm = ChatOpenAI(model="gpt-4o", temperature=0)

@gateway.protect
def run_langchain_pipeline(query: str):
    # 1. Retrieve raw documents
    docs = retriever.get_relevant_documents(query)
    context_str = "\n\n".join([d.page_content for d in docs])

    # 2. Invoke model with prompt
    prompt = f"Context:\n{context_str}\n\nQuestion: {query}"
    response = llm.invoke(prompt)

    return response.content, context_str

Plug Rekha into LlamaIndex's QueryEngine workflow.

llamaindex_rekha.py 
from llama_index.core import VectorStoreIndex
from rekha import RekhaGateway

gateway = RekhaGateway()
query_engine = index.as_query_engine(similarity_top_k=6)

@gateway.protect
def llamaindex_query(query_text: str):
    response = query_engine.query(query_text)
    
    # Extract retrieved source nodes as context
    context = "\n\n".join([n.node.get_content() for n in response.source_nodes])
    return str(response), context

A production FastAPI service exposing SSE streaming with zero-lag Inbound Guard and Satya Praman verification headers.

api_server.py 
from fastapi import FastAPI, HTTPException, Response
from pydantic import BaseModel
from rekha import RekhaGateway

app = FastAPI(title="Enterprise RAG Service")
gateway = RekhaGateway()

class ChatRequest(BaseModel):
    query: str

@app.post("/v1/chat")
async def chat_endpoint(req: ChatRequest, response: Response):
    # Execute pipeline with telemetry
    result = gateway.execute(
        query=req.query,
        rag_executor=my_internal_rag_worker
    )

    # Add production observability headers
    response.headers["X-Rekha-Latency-Ms"] = str(round(result.total_overhead_latency_ms, 2))
    response.headers["X-Rekha-Source"] = result.source
    
    if result.source == "BLOCKED_GUARD":
        raise HTTPException(status_code=400, detail=result.final_output)

    return {
        "response": result.final_output,
        "source": result.source,
        "tokens_pruned": result.optimizer.pruning_ratio if result.optimizer else 0.0
    }

Using Rekha directly with official OpenAI or Anthropic Python clients.

raw_openai_rekha.py 
from openai import OpenAI
from rekha import RekhaGateway

client = OpenAI()
gateway = RekhaGateway()

def generate_answer(query: str):

            {"role": "system", "content": f"Context:\n{context}"},

Configuration Reference

The 5 Control Layers in Detail

STAGE 01 ~37 ms

Layer 1: Inbound Guard Gate

Evaluates raw queries against jailbreak attacks, prompt leaks, and sensitive PII prior to any database lookups. 

# Customizing Guard Gate
gateway.guard.injection_confidence_threshold = 0.85
gateway.guard.add_custom_pii_pattern(
    pattern_name="INTERNAL_BADGE_ID",
    regex_pattern=r"EMP-[0-9]{6}"
)
  • Deterministic Regex Sanitization: Masks credit cards, SSNs, and bearer tokens before pipeline execution.
  • Non-Autoregressive Safety Classification: Immunized against generative prompt injection tricks.
STAGE 02 <5 ms (Hit) / ~35 ms (Miss)

Layer 2: Smriti Gate (Intent Cache)

Pre-emptively returns authoritative answers for canonical enterprise FAQ queries, skipping all vector DB and LLM inference. 

# Pre-registering canonical organizational FAQ intents
gateway.register_canonical_faq(
    intent_id="enterprise_billing_sla",
    description="Inquiries regarding payment terms, billing cycle, or net-30 invoices.",
    verified_answer="Enterprise invoices are issued Net-30 on the 1st of each calendar month."
)

Advantage over Naive Cosine Cache: Standard cosine caches drift and cause false positive cache hits. Smriti uses discrete intent cluster centers with adaptive confidence bounds.

STAGE 03 ~38 ms

Layer 3: Disha Router (Query Dispatch)

Dispatches queries to one of three pathways: BYPASS_NO_RAG (conversational greetings), STRUCTURED_TOOL (SQL/Analytics), or VECTOR_SEARCH. 

# Returns typed RoutingDecision in sub-38ms
decision = gateway.router.evaluate("How many units did we sell in Q3?")
print(decision.destination)       # "STRUCTURED_TOOL"
print(decision.target_namespace)  # "sql_sales_ledger"
STAGE 04 ~69 ms (Prunes 54%)

Layer 4: Samkshep Slicer (Context Optimizer)

Micro-slices retrieved chunks into atomic semantic sentences, scores them in parallel, and packs the highest-signal units into your token budget while preserving exact document reading order. 

# Syntax-aware micro-slicing protects tables & code blocks
opt_res = gateway.optimizer.optimize(
    query="What are the interest rate bounds?",
    documents=raw_rag_chunks,
    target_reduction=0.60  # Prunes 60% of noise tokens
)
print(opt_res.stats.original_tokens)   # 4,200
print(opt_res.stats.optimized_tokens)  # 1,680

Zero Token-Amputation: Unlike token-dropping methods that amputate parentheses or negation words (causing inverted answers), Samkshep operates on grammar-complete sentence boundaries.

STAGE 05 ~72 ms

Layer 5: Satya Praman (Outbound Grounding)

Audits the synthesized answer before it reaches the user. Performs exact regex entity anchor verification (checking that every dollar amount, date, or percentage in the answer exists in the source text) and enforces negative policy constraints. 

# Verification returns typed decision
ver_res = gateway.verifier.verify(
    query="What is the annual SLA warranty?",
    reference_context=retrieved_context,
    generated_answer=llm_answer,
    negative_constraints=["Never promise 100% uptime"]
)

if ver_res.decision == "BLOCK_AND_FALLBACK":
    print("Violation detected:", ver_res.fallback_message)
Production Deployment

Air-Gapped Dockerfile

For enterprise VPCs with zero outbound internet access, pre-bake the local model weights into your container image during your CI build step.

Dockerfile 
FROM python:3.10-slim

WORKDIR /app

# Install dependencies
RUN pip install --no-cache-dir minelabs-rekha fastapi uvicorn

# Pre-cache local weights into image during build
ENV REKHA_OFFLINE_MODE=1
RUN python -c "from rekha import RekhaGateway; RekhaGateway()"

# Copy application code
COPY . /app

# Run air-gapped without external network access
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

Telemetry & HTTP Headers

Every execution of gateway.execute(...) returns structured Pydantic metrics ready to attach to API responses or emit into Datadog, Prometheus, or OpenTelemetry.

Header / Attribute Type Example Value Description
total_overhead_latency_ms float 182.4 Total cumulative Rekha gating latency across all 5 stages.
source str "RAG_VERIFIED" Execution source: CACHE, BLOCKED_GUARD, RAG_VERIFIED, or RAG_FALLBACK.
optimizer.pruning_ratio float 0.548 Fraction of context noise pruned (e.g. 54.8% tokens saved).
verifier.entity_matches list [{entity: "$250", verified: true}] Extracted numerical/date entity anchor validation results.

API Reference: RekhaGateway

Core class signature and initialization arguments in rekha.gateway. 

class RekhaGateway:
    def __init__(
        self,
        enable_guard: bool = True,
        enable_cache: bool = True,
        enable_router: bool = True,
        enable_optimizer: bool = True,
        enable_verifier: bool = True,
        negative_constraints: Optional[List[str]] = None,
        target_context_reduction: float = 0.50
    ):
        ...
Methods:
protect(func): Decorator wrapping an existing RAG function taking (query) and returning (answer, raw_context).
execute(query, rag_executor): Functional execution passing query through all 5 layers with complete typed result return.
register_canonical_faq(intent_id, description, verified_answer): Registers intent cluster for sub-5ms cache bypass.
