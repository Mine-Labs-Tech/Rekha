The Architectural Dilemma

The 3 Structural Flaws in Production RAG

Why wrapping a vector database with an LLM prompt fails in enterprise production environments.

01

The Latency Trap of Guardrails

Using a secondary LLM (like NeMo or GPT-4o) to police your primary LLM adds 2,500ms to 4,000ms of lag and doubles your monthly API invoice.

02

The Syntax Amputation Flaw

Token-dropping compressors (like LLMLingua) delete characters by perplexity—destroying Markdown table columns, breaking JSON syntax, and dropping crucial words like "not".

03

The Silent Hallucination Risk

LLMs hallucinate critical numbers, pricing tiers, and dates when surrounded by noisy retrieved context. Offline evaluation frameworks (Ragas) cannot run in-flight on live user streams.

Developer Ergonomics

Zero Migration Friction

You do not rebuild vector embeddings, migrate clusters, or modify prompts. Adding Rekha is just one Python decorator: @gateway.protect.

rag_pipeline.py 
import openai
from rekha import RekhaGateway        # 1. Import Rekha

gateway = RekhaGateway()              # 2. Local non-autoregressive weights (0 API keys)

@gateway.protect                      # 3. Apply protection decorator
def my_rag_pipeline(user_query: str):
    chunks = vector_db.similarity_search(user_query, k=5)
    context = "\n\n".join([c.page_content for c in chunks])
    
    # Context is automatically sliced via Samkshep (54% token reduction)
    # Injections are intercepted in ~35ms before reaching this line
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": f"Answer based on:\n{context}"},
            {"role": "user", "content": user_query}
        ]
    )
    # Satya Praman verifies claims & numerical entities before stream
    return response.choices[0].message.content, context

Rekha vs Point Solutions

Why single-purpose tools fail in production and how Rekha unifies them into a sub-35ms control plane.

System Mechanism Latency Architectural Limitation Rekha Control Plane
Microsoft LLMLingua Token Perplexity Drop ~120 ms Syntax Amputation: Deletes closing brackets }, corrupts Markdown tables, and drops negation words ("not"). Preserves table rows, JSON keys, and reading order intact via Samkshep.
Nvidia NeMo Guardrails Secondary LLM Calls 2,500 – 4,000 ms Generative Delay: Calling another LLM doubles API bills and introduces unacceptable user wait times. Sub-35ms non-autoregressive encoder runs locally for $0.00.
Cohere Rerank Cross-Encoder Chunk Scoring ~150 ms No Noise Pruning: Reorders chunks but preserves all paragraph clutter. Token bills remain 100%. Micro-slices within chunks and packs high-value clauses knapsack-style.
Ragas / TruLens LLM-as-a-Judge Eval 3,000 – 6,000 ms Offline Only: Useful for post-hoc testing, impossible to run synchronously on live user chats. Live in-flight grounding (~72ms) via Satya Praman before streaming.
Redis LangCache Vector Cosine Distance ~20 ms Threshold Drift: Cosine distance falsely maps opposing intents ("How to cancel?" vs "How to upgrade?"). Canonical Intent Clusters via Smriti Gate guarantee 99%+ semantic fidelity.
Production Deployment

Air-Gapped & Zero-Internet Ready

Weights (~700MB) are automatically downloaded to your local cache on first initialization. For isolated VPCs, pre-cache them in your Docker build.

Dockerfile (Offline Production VPC) Docker Build
FROM python:3.10-slim
WORKDIR /app
RUN pip install --no-cache-dir rekha
# Bake decision weights directly into image layer
RUN python -c "import laya; from laya import Laya; Laya()"
ENV REKHA_AIRGAPPED=true
# Runs completely offline with zero external network access
CMD ["uvicorn", "main:app", "--host", "0.0.0.0"]
